Documentation

Everything you need to use PSZ.

PSZ is an encrypted project archive format. Each archive is paired with a generated unpacker.

name.psz

The encrypted project archive. Project files are packed as TAR and encrypted with AES-256-GCM.

name.psz-data.lor

The matching unpacker containing the key and code required to decrypt that specific archive.

Installation

Install PSZ directly from GitHub. 

pip install git+https://github.com/SlabyLol/psz.git

Or after cloning the repository: 

pip install -e .

Python 3.9+ is required.

Make

Create an encrypted archive from a project directory: 

psz make ./project -o release.psz

This creates: 

release.psz
release.psz-data.lor

You can also create an archive from a single file: 

psz make file.txt -o one.psz

Unpacker languages

The generated .psz-data.lor can contain an unpacker for different environments. 

psz make ./project -o release.psz --lang python
psz make ./project -o release.psz --lang php
psz make ./project -o release.psz --lang js
psz make ./project -o release.psz --lang html

The filename remains: release.psz-data.lor

Open / Extract

Using the PSZ CLI: 

psz open release.psz release.psz-data.lor -o out/

You can also extract selected members: 

psz open release.psz release.psz-data.lor -o out/ -m path/inside.txt

List archive contents

psz list release.psz release.psz-data.lor

This decrypts the archive and lists the safe TAR members contained inside.

Python API

from pathlib import Path
from psz import (
    create_archive,
    open_archive,
    list_archive_members,
)

create_archive(
    Path("project"),
    Path("release.psz")
)

members = list_archive_members(
    Path("release.psz"),
    Path("release.psz-data.lor")
)

open_archive(
    Path("release.psz"),
    Path("release.psz-data.lor"),
    Path("out")
)

Archive format

The current PSZ implementation uses the following structure: 

PSZ1
VERSION: 1
NONCE: 12 bytes
CIPHERTEXT: AES-256-GCM encrypted TAR

A fresh random 256-bit key is generated for every archive. The nonce is 12 bytes and AES-GCM authentication uses a 128-bit tag.

Security

  • AES-256-GCM authenticated encryption
  • A new random key for every archive
  • The key is stored inside the matching unpacker
  • The archive and unpacker are paired
  • Unsafe absolute and parent paths are rejected during extraction

If the archive content is sensitive, do not publish or share the matching .psz-data.lor.

Docker

docker build -t psz .

docker run --rm \
  -v $(pwd):/data \
  psz make /data/myfolder -o /data/out.psz

GitHub Actions

PSZ can be used in CI workflows to create encrypted release artifacts automatically. 

psz make ./dist -o release.psz
